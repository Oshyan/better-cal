## Design Context

### Users

Better-Cal is built for one owner managing a real personal calendar every day. The owner is comfortable with advanced calendar features, but should not need security or infrastructure vocabulary to understand a warning or decide what to do.

### Brand Personality

Plainspoken, calm, practical, and honest. The interface should explain what happened, what remains safe, and what action is available without making routine maintenance feel alarming.

### Aesthetic Direction

Preserve the existing compact, desktop-first interface and its phone treatment. Use the established warning color, cards, buttons, spacing, light/dark themes, and inline calendar settings rather than introducing a new visual language.

### Design Principles

- A warning affordance must be actionable or clearly informational; never imply an action that does not exist.
- Put decisions in Review as well as at the object they affect, so the owner has one reliable inbox for required choices.
- Describe the user-visible consequence first, then the reason, then the available choices.
- Keep owner-facing verification short and recognizable; retain exhaustive technical evidence separately.
- Preserve existing data and make that preservation explicit when automatic updates are paused.
